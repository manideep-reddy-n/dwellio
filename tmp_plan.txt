## 1. Resident Timeline — Audit Detail

### What exists (working plumbing)

```mermaid
flowchart LR
  subgraph writers [Event Writers - 2 of 5]
    OS[OccupancyService]
    PS[PaymentService]
  end
  subgraph store [Persistence]
    AE[(activity_events V23)]
  end
  subgraph read [Read path]
    TC[TimelineController]
    FE[vertical-timeline.tsx]
  end
  OS -->|MOVE_IN TRANSFER MOVE_OUT| AE
  PS -->|CHARGE_CREATED PAYMENT_RECORDED| AE
  AE --> TC --> FE
```

| Component | Path | Status |
|-----------|------|--------|
| Table + entity | [`V23__activity_events.sql`](backend/src/main/resources/db/migration/V23__activity_events.sql), [`ActivityEvent.java`](backend/src/main/java/com/dwellio/domain/entity/ActivityEvent.java) | OK |
| Service | [`ActivityEventService.java`](backend/src/main/java/com/dwellio/activity/service/ActivityEventService.java) | OK |
| APIs | [`TimelineController.java`](backend/src/main/java/com/dwellio/activity/controller/TimelineController.java) | OK (no pagination) |
| Frontend | [`resident/timeline`](frontend/src/app/app/[orgSlug]/resident/timeline/page.tsx), [`operations/timeline`](frontend/src/app/app/[orgSlug]/operations/timeline/page.tsx) | OK but masks errors |

### Event writers today

| Domain | Required events | Implemented | Missing |
|--------|-----------------|-------------|---------|
| **Billing** | Charge, Payment, Late fee, Adjustment | Charge + Payment on forward paths only | Late fee, adjustment; no backfill from existing `payments` |
| **Accommodation** | Allocated, Released, Transferred, Room/Bed changed | MOVE_IN, TRANSFER, MOVE_OUT on forward paths | Separate ROOM_CHANGED/BED_CHANGED types; no backfill from `occupancies` |
| **Complaints** | Created, Assigned, Resolved, Reopened, Closed | None | Wire [`ComplaintService`](backend/src/main/java/com/dwellio/complaint/service/ComplaintService.java) |
| **Reviews** | Submitted, Updated | None | Wire [`ReviewService`](backend/src/main/java/com/dwellio/review/service/ReviewService.java) |
| **Membership** | Approved, Joined, Suspended, Left | None | Wire [`JoinRequestService`](backend/src/main/java/com/dwellio/joinrequest/service/JoinRequestService.java), [`LeaveRequestService`](backend/src/main/java/com/dwellio/leaverequest/service/LeaveRequestService.java), membership suspend |

### Why timeline appears empty

1. **No backfill** — unlike ledger ([`LedgerService.backfillOrganization`](backend/src/main/java/com/dwellio/ledger/service/LedgerService.java)), activity events are never seeded from historical data.
2. **Demo data predates writers** — [`DevDemoDataSeeder`](backend/src/main/java/com/dwellio/dev/DevDemoDataSeeder.java) skips re-seed when org exists; complaints/reviews/memberships produce zero timeline rows.
3. **Billing events require payment sync** — visiting timeline does not trigger `syncMonthlyPayments`; only payment list APIs or 2 AM scheduler do.
4. **Frontend** — `useTimeline` defaults to `[]` on error; resident nav has no Timeline/Ledger links in [`resident-bottom-nav.tsx`](frontend/src/components/resident/resident-bottom-nav.tsx).

### Fix plan (Phase A)

- Add **`ActivityEventBackfillService`** invoked from `MetricsProjectionService.rebuild()` (mirror ledger pattern):
  - Payments → billing events
  - Occupancies (history) → accommodation events with historical `occurredAt`
  - Complaints → complaint events from `created_at` / `assigned_at` / `resolved_at`
  - Reviews → review events
  - Memberships → join/leave from `memberships` + join/leave requests
- Add **`ActivityEventPublisher`** helper with typed methods per domain (avoid scattered string event types).
- Wire all service mutation points listed above.
- Add `POST /organizations/{id}/timeline/rebuild` (ops) or piggyback on existing metrics rebuild.
- Frontend: error state in timeline; add nav links; invalidate timeline on complaint/occupancy/membership mutations.

### Fix plan (Phase B)

**V25 migration** — extend `organization_metrics_cache`:

```sql
-- Resident lifecycle
move_ins_month INT, move_outs_month INT,
avg_stay_days DECIMAL(8,2), turnover_rate DECIMAL(5,2),

-- Complaint SLA (org-level default targets in org settings or constants)
sla_first_response_hours DECIMAL(6,2) DEFAULT 24,
sla_resolution_hours DECIMAL(8,2) DEFAULT 72,
sla_compliance_rate DECIMAL(5,2),

-- Meals (nullable for non-food orgs)

meal_ratings_trend_json JSONB
```

**[`MetricsAggregateRepository`](backend/src/main/java/com/dwellio/metrics/projection/MetricsAggregateRepository.java)** — add queries for occupancy lifecycle, SLA violations (compare `first_response_at`/`resolved_at` vs org SLA), meal aggregates.

**Dashboard consolidation (Phase I)** — replace fragmented cards with sectioned layout:

- Financial Operations (reuse revenue panel + pending payments KPI)
- Accommodation Operations (occupancy, vacant beds/units, move-in/out)
- Resident Operations (active, avg stay, turnover)
- Complaint Operations (open, SLA compliance, violations)
- Review Operations (rating, count)
- Meal Operations (HOSTEL/PG/CO_LIVING only)

Reuse [`MetricsEventListener`](backend/src/main/java/com/dwellio/metrics/event/MetricsEventListener.java) pattern; add listeners for occupancy → lifecycle metrics refresh.

```mermaid
flowchart TD
  BR[billing_rules + org billing_mode]
```

- Frontend: pass `occupancyClassification` from [`accommodation-manager.tsx`](frontend/src/components/accommodation/accommodation-manager.tsx) on allocate

## Pre-implementation checklist (do first in code)

1. Run `POST /organizations/{id}/metrics/rebuild` on demo org — confirm ledger backfill works but timeline stays empty (validates audit).
2. Create one manual charge + one allocate — confirm 2 timeline rows appear (validates forward path).
3. Query `SELECT count(*) FROM activity_events` — baseline empty vs populated.
4. Confirm `npm run dev` uses webpack (nested route 404 fix from prior session).

No new feature code should ship until Phase A backfill + writers land; otherwise dashboard and profile work will also appear broken on existing data.
